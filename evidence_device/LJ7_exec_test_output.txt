INTERPRETATION
--------------
Exit code 42 came from the ELF32/ARM probe, so a 32-bit process started and ran
to completion. A kernel without AArch32 support fails execve with ENOEXEC and
returns no exit code at all, so 42 is a real execution and not a fallback. The
64-bit probe returning 43 shows the launch mechanism itself is sound.

SELinux domain is untrusted_app_27, confirming targetSdk 28 selected the legacy
domain that is granted app_data_file:file execute_no_trans. The earlier run's
"error=13, Permission denied" came from building the test at targetSdk 34, which
selects a domain with no such rule.

The firmware carries no 32-bit linker or libc.so, and ro.zygote is zygote64 with
abilist arm64-v8a. That is why Package Manager reports no 32-bit ABI and refuses
to install the game's armeabi-v7a libraries. It is a userspace restriction only;
the kernel underneath executes AArch32 natively.

Consequence: a virtualisation app that supplies its own 32-bit Android userspace
(VMOS Pro with a 32-bit ROM, VPhoneOS, F1 VM) can run Fireman 1.0.9 on this phone
on the same cores, with no CPU emulation.

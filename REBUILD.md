## Коротко

Я **проверил вашу идею на практике**, а не на словах. Восстановил Unity-проект из APK
инструментом AssetRipper. Результат: **проект восстановился почти полностью** —
299 C#-файлов с настоящим кодом, 6 сцен, 70 префабов.

**Значит, «переписать приложение» технически возможно.** Но есть блокер, который
я не могу обойти без вас: **лицензия Unity**.

## Качество восстановленного кода

Не заглушки. Пример реального кода из `Utils.cs`:

```csharp
public static string ToHash(this string str)
{
    StringBuilder stringBuilder = new StringBuilder();
    byte[] buffer = Array.ConvertAll(str.ToCharArray(), (char x) => (byte)x);
    byte[] array = new MD5CryptoServiceProvider().ComputeHash(buffer);
    foreach (byte b in array) stringBuilder.Append(b.ToString("X2"));
    return stringBuilder.ToString();
}
```

## Что нужно для сборки arm64

| Компонент | Статус |
|---|---|
| Восстановленный проект | **есть** |
| Unity 6 LTS (4.5 ГБ) | скачивается, проверено: HTTP 200 |
| NDK для IL2CPP | **нужно доустановить** (~3 ГБ) |
| Место на диске | есть (60 ГБ свободно) |
| **Лицензия Unity** | **НЕТ — это блокер** |
| Ваш Unity-аккаунт | **нужен** |

Unity в batch-режиме **не запустится без активации лицензии**. Бесплатная
лицензия Unity Personal существует, но её нужно активировать под аккаунтом —
создавать аккаунт за вас я не буду.

## Почему это не «одна кнопка», даже с лицензией

Проект — Unity **5.3.8f1 (2016 год)**. Открыть его в Unity 6 и собрать — это
миграция через 11 лет версий:

1. **Световые карты Enlighten.** В современной Unity Enlighten удалён. Запечённое
   освещение уровней будет потеряно или потребует перезапекания.
2. **32 устаревших шейдера.** Шейдеры Unity 5 не компилируются в Unity 6,
   особенно `Unlit - Masked Colored`, `GUI - Text Shader (AlphaClip)`.
3. **NGUI старой версии.** 130 UI-скриптов используют API, часть которых
   удалена. Их придётся править.
4. **Mono → IL2CPP.** Сборка под arm64 возможна **только** на IL2CPP.
   Сам код C# совместим, но реклама и Google Play Games — нативные плагины,
   их arm64-версии нужны отдельно (или их придётся отключить).
5. **Удалённые API.** `Application.LoadLevel`, старый `WWW`,
   `ParticleEmitter`, `GUIText` и прочее.

Реалистичная оценка: **дни работы с множеством итераций**, а не часы. И это
при условии, что исходники NGUI/рекламы совместимы.

## Что я рекомендую

### Вариант А — играть сейчас, без пересборки (5 минут)

**VPhoneOS.** Это единственный рабочий способ запуска 32-битных приложений на
64-бит-only телефонах — подтверждено независимыми тестами, в том числе на
Pixel 8 Pro, где ситуация идентична вашей.

Пошагово:

1. Установите **VPhoneOS** из Google Play.
2. Создайте виртуальную машину: **Android 7.1.2**, архитектура
   **«64-bit & 32-bit mixed»**.
3. В настройках разработчика телефона отключите **ограничение дочерних
   процессов** (приложение само подскажет).
4. Внутри ВМ откройте браузер и скачайте APK:
   `https://github.com/Pavel1778/Reset-fireman/releases/download/v1.0.9-android-fix.1/Fireman_1.0.9_full_original.apk`
5. Установите и играйте.

Важно: берите **`Fireman_1.0.9_full_original.apk`** — у него оригинальная подпись
Magma Mobile, и он не конфликтует с другими копиями.

Минус: эмуляция всегда медленнее нативной работы. Для аркады 2013 года это
некритично.

### Вариант Б — настоящая пересборка под arm64

Возможна. Для этого мне нужно от вас:

1. **Unity-аккаунт** (email + пароль, либо вы сами активируете лицензию и
   положите файл `Unity_lic.ulf`). Без этого Unity не запустится.
2. **Подтверждение**, что вы готовы к многоэтапной работе: сначала пробная
   сборка хотя бы одной сцены, потом исправление шейдеров и NGUI, потом
   полная сборка и подпись.
3. Решение по рекламе и Google Play Games: их arm64-версии, скорее всего,
   придётся **отключить** — в 2016 году 64-битных версий этих плагинов не
   существовало.

Первый шаг, который я могу сделать сразу после получения лицензии: открыть
проект в Unity 6 в batch-режиме и собрать **диагностическую сборку одной
сцены**, чтобы точно увидеть список ошибок компиляции. Это займёт ~1 час.

## Ответ на вопрос про пробник

`Fireman_Install_Probe.apk` лежит в релизе. Прямая ссылка:

```
https://github.com/Pavel1778/Reset-fireman/releases/download/v1.0.9-android-fix.1/Fireman_Install_Probe.apk
```

Проверено: HTTP 200, 12 689 байт. Состав: только `AndroidManifest.xml`,
`resources.arsc`, `classes.dex` — **нативных библиотек нет**, поэтому проверка
ABI его не коснётся. minSdk 24, targetSdk 34.

Если он установится, а игра нет — причина точно в 32-битности.
Если и он не установится — блокирует прошивка (Play Protect или HiOS).

Настройки «Расширенная защита» может не быть под таким именем. Ищите в
HiOS: **Настройки → Безопасность → Play Protect** и **Настройки → Приложения →
Особый доступ → Установка неизвестных приложений**.
